# Уточнения и противоречия ТЗ

ТЗ использовано как требования к исправлениям, а исходные каталоги — как свидетельства сохранённой документации. Неоднозначность не устранялась выдуманными данными.

1. **530 совпадений примеров v5/v6.** Буквальное сравнение без номера версии и пустых строк даёт 466; ещё 64 отличаются конечными пробелами. Число 530 из ТЗ требует дополнительной нормализации. Все оставшиеся 44 разобраны: 20 отличаются внутренними пробелами, 24 содержательно. Код v5 сохранён; подробности в `v5-example-review.md`.
2. **Запрет трёх однострочных «примеров» не универсален.** В v1/v2 операторы `+` и `-` содержат по три самостоятельные синтаксические формы, например бинарную, унарную и сам знак. Это `syntax_illustration`, а не разрезанная программа. Проверка оставляет узкое исключение для иллюстраций операторов; отдельная директива `//@version=N` запрещена всегда. Две пары таких форм в каждой из v3/v4 также сохранены.
3. **Не менять description и одновременно удалить пустой текст.** Сохранить старую ссылку после удаления её цели невозможно. Пустые `description` обнулены; донор записан исключительно в `description_hint`. Без донора выставлено `description_missing: true`. Это не подстановка текста другой версии в первичное описание.
4. **Пустой текст встречался вне result.** `fda68027fd1128ed` использовался в 84 `result.description` и в 84 `examples.note`. Для целостности очищены обе группы ссылок. Видимый текст не утрачен: все три языковых поля были пусты.
5. **Донор не всегда безопасен.** Неоднозначные перегрузки старого `rsi` и коллективные параметры нельзя сопоставлять по позиции автоматически. Добавлено 73 проверяемых подсказки, 24 пробела сохранены и перечислены в CSV. Типы и обязательность не переписаны по аналогии.
6. **Неизменность экспорта в шаге 4 относится к правке UI.** Категорийное отображение результата не меняет поле `result`. Отдельная миграция шага 2 удаляет пустые ссылки, что явно разрешено тем же ТЗ; экспорт закономерно отражает исправленный каталог.
7. **«Визуально не изменилась» и увеличение шрифта.** Увеличение минимального шрифта и контраста по шагу 5 намеренно меняет изображение относительно исходника. Неизменность проверяется при объединении CSS после этих исправлений; ширины 390/800/1000/1400 проверяются отдельно.
8. **Лицензия не выводится из домена источника.** Владелец выбрал MIT для собственного кода. Сторонние тексты, примеры и переводы отделены в NOTICE/THIRD_PARTY.md; наличие ссылки на GitHub или TradingView не объявлено разрешением на распространение. Публикация не выполнялась.
9. **Устаревший отчёт допускается исключить.** Выбран предусмотренный шагом 9 вариант удаления `pine-result-less-functions.md` из поставки. Восстанавливать ошибочный мегабайтный отчёт параллельно каталогам не требуется; исходник остаётся в baseline-теге, а итоговые метрики и QA воспроизводятся инструментами.
10. **Порядок валидации и коммитов.** Данные мигрировались последовательно и каждый переход проверялся на идемпотентность. Изменения UI и тестов готовились параллельно, поэтому полный расширенный браузерный прогон выполняется на интегрированной конечной сборке. Отдельные коммиты соответствуют шагам; baseline сохранён. Промежуточным состояниям не приписывается прохождение ещё не написанных тестов.

## Уточнения по повторному аудиту 17 октября 2026

Владелец поручил исправить подтверждённые и необходимые замечания. Приоритет отдан поведению поиска, воспроизводимости аудита, защите целостности данных и доступности интерфейса.

11. **Порог стемминга не решает проблему целиком.** Простая замена `>5` на `>=5` не обрабатывает `линий` и `меток`, не исправляет ранжирование `массивы`/`таблицы` и ухудшает результат `линию`. Словоформы учитываются у русских синонимов; короткие API-имена и поиск по тексту сохраняют прежние ограничения. Регрессии проверяют реальные карточки и отсутствие ложных совпадений.
12. **Выборка аудита должна быть независима от результата.** Список 574 карточек восстановлен из `catalog-v5.js` исходного коммита `273ea751ea5ce00ae3150eb1d8e1a62942ac2354` и сохранён вместе с SHA-256 исходного файла в `tools/migrations/v5_example_merge_manifest.json`. Эвристика «все многострочные примеры v5» выбирает 600 карточек и не заменяет исходную выборку. Аудит не читает старый результат как входные данные; удалённый отчёт восстанавливается побайтово, отсутствие канонической карточки вызывает ошибку.
13. **Очистка истории обязана учитывать все ссылки.** Перечень полей в повторном ТЗ пропускает `description_supplements`, `related[].note` и `default_contracts.*.evidence[].text_ref`. Его буквальное применение удалило бы два используемых текста описания `cross` v4. Сохраняются все достижимые тексты, удаляются только 137 осиротевших записей. Проверки отсутствующих, пустых и лишних текстов применяются к каталогам и истории.
14. **Агрегаты имеют разную семантику.** `structure_counts` считает уникальные `structure.key` по ролям; например, 1298 API-карточек v5 соответствуют 993 уникальным структурам. История хранит объединение параметров, типов и обязательности по всем перегрузкам версии. Валидатор проверяет именно эти правила, не подменяет их количеством карточек или одной перегрузкой.
15. **Неподтверждённые дефекты не требуют исправлений.** Playwright 1.64.0 опубликован в PyPI 13 октября 2026 и успешно использован локально; версия сохранена. Baseline-тег существует. Описанная HTML-инъекция через `&quot;` не воспроизвелась: сущность не завершает значение атрибута. Fallback копирования уже очищает контейнер, отсутствие семейства уже обрабатывается с повтором. Эти участки не переписывались.
16. **Улучшения UI сохраняют смысл состояния.** Панель источников временно скрывает баннер и объявляет режим, но не удаляет ID выбранной карточки. В списках сравнения отмечено отсутствие записи в сохранённой версии, без утверждения об отсутствии самой конструкции в языке.
17. **Косметическая чистка не является исправлением поломки.** Повторные CSS-селекторы большей частью дополняют свойства; механическое объединение медиаблоков меняет каскад. CSS сохранён. Windows-имена команд в QA отражают фактический запуск и не мешают работе на других ОС. `test-results/` исключён из Git; его наличие после QA ожидаемо, а проверенные отчёты не признаны устаревшими только по имени файла.
