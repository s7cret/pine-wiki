# Проверка склейки примеров v5 (Z-01)

Проверены сохранённые каталоги; Pine-код не компилировался, актуальные страницы TradingView не использовались для подмены исторического кода. В 574 карточках 5 354 однострочных элемента составляют по одной группе. Склейка сохраняет каждую строку буквально, соединяет их `\n` и сохраняет источник первого элемента. Общий счётчик элементов v5 меняется с 5 667 на 887. Пустые строки, отсутствующие в снимке, не восстанавливаются.

Проверка воспроизводится командой `python tools/audit_v5_examples.py`; машиночитаемый результат с ID всех 574 карточек и diff каждого из 44 расхождений находится в `docs/v5-example-audit.json`. Соответствие ищется среди всех перегрузок того же имени **и категории**, поэтому одноимённые функции, типы и переменные не смешиваются.

Число 530 из ТЗ требует уточнения: при исключении только номера версии и пустых строк совпадают 466 карточек. Ещё 64 отличаются исключительно пробелами в конце строк. Поэтому 530 получается при дополнительном игнорировании конечных пробелов; отступы Pine и пробелы внутри строк при сравнении сохраняются. Миграция не удаляет даже конечные пробелы.

## Все 44 оставшихся расхождения

В таблице суффикс перегрузки относится к ID вида `primary:v5:<категория>:<имя>:overload:<N>`. Число строк в группах — число карточек; сумма равна 44. Конкретные пары и построчные diff сохранены в JSON-аудите. Решение для каждой группы: сохранить v5, не копировать код v6.

## Четыре однострочных пары v3/v4

Проверены `primary:v3:operators:+:overload:0`, `primary:v3:operators:-:overload:0`, `primary:v4:operators:+:overload:0` и `primary:v4:operators:-:overload:0`. Их пары — соответственно `expr1 + expr2` / `+ expr` и `expr1 - expr2` / `- expr`: самостоятельные бинарная и унарная формы оператора. Они не являются построчно нарезанным скриптом, поэтому сохраняются как два примера.
