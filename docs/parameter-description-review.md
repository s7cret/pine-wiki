# Описания параметров и пустые редакторские тексты (Z-03)

Миграция `tools/migrations/02_parameter_description_hints.py` работает только с сохранёнными каталогами и не заменяет доказательства текущей версии текстом другой версии. Скрипт повторяемый, использует стандартную библиотеку; после второго запуска все шесть файлов каталогов побайтово совпадают с первым результатом.

| Версия | Параметров без первичного описания | С подсказкой | Без подсказки |
|---|---:|---:|---:|
| v3 | 44 | 32 | 12 |
| v4 | 53 | 41 | 12 |
| Всего | 97 | 73 | 24 |

Полный CSV с четырьмя столбцами `version,function,parameter,entry_id` создаётся `python tools/report_empty_params.py --output docs/empty-parameter-descriptions.csv`. Флаг `--without-hint` создаёт сокращённый отчёт `docs/parameter-descriptions-without-hints.csv` с 24 оставшимися пробелами. Наличие подсказки не превращает первичное описание в документированное.

## Схема и происхождение

```json
{
  "description": null,
  "description_hint": {
    "version": 5,
    "entry_id": "primary:v5:functions:na:overload:0",
    "parameter": "x",
    "text": "ed28d1215ee689df",
    "sources": [{"url": "https://www.tradingview.com/pine-script-reference/v5/#fun_na", "label": "TradingView · v5", "sha256": "..."}]
  }
}
```

`text` указывает на неизменённую копию текста донора в локальном `texts`, поэтому карточка не требует загрузки другой версии. `entry_id`, `version` и `parameter` позволяют проверить и открыть конкретный источник. Поле `description_status: not_documented_in_snapshot` сохранено. Если безопасного донора нет, добавляется `description_missing: true`, а `description_hint` отсутствует.

Поиск выполняется по существующему семейству и категории: для v3 — v4, затем v5, v6; для v4 — v5, затем v6. Сначала проверяется совпадение имени параметра. Несколько перегрузок допускаются только при полном совпадении их текстовых объектов; выбирается первая в исходном порядке. Подсказка никогда не становится донором для другой подсказки.

Явно проверены переименования единственного аргумента: `abs/log/log10/sqrt/sign/exp/ceil/floor`: `x` → `number`; `asin/acos/atan`: `x` → `angle`; `fixnan/cum`: `x` → `source`. Для двух операндов `cross` проверены `x` → `source1` и `y` → `source2`. Соответствия ограничены точным ID семейства и перечислены в `RENAMED_PARAMETERS`; позиционное и нечёткое сопоставление не применяется. Это подсказки с предупреждением, а не утверждение о полной неизменности семантики версии.

## Почему оставлены 24 пробела

- `min`, `max`, `avg`: v3/v4 перечисляют отдельные аргументы, а донор v5 описывает единый коллективный параметр `number0, number1, ...`. Приписывать групповой текст отдельному аргументу без явного правила соответствия нельзя.
- `rsi(x, y)`: сохранённые v3/v4 допускают для `y` `integer, series`, тогда как `ta.rsi` v5 описывает `source, length`. Перенос описания длины на старый перегруженный `y` мог бы исказить контракт; оба параметра оставлены без подсказки.
- `array.from(..args)` v4: рядом уже присутствует другой параметр `arg0, arg1, ...`. Механическое отождествление спорного `..args` с группой v5 закрепило бы возможный артефакт разбора. Параметр и его отсутствие типа сохранены как известный пробел.

## Уточнения требований

ТЗ одновременно требует не подставлять донор в `description` и удалить пустой текст из `texts`. Поэтому `description` обнуляется у всех 97 параметров, включая 73 с подсказками; донор хранится только в `description_hint`. Сохранение старой ссылки при удалении текста создало бы битые ссылки.

Пустой `fda68027fd1128ed` использовался в 84 `result.description` **и** в 84 `examples.note`, хотя ТЗ упоминает только результаты. Миграция обнуляет обе группы ссылок перед удалением текста. По версиям это 7, 9, 19, 18, 16 и 15 карточек. Пустой `1f28bab001938f5e` удалён из v3/v4. Единственный сохранённый пустой текст с `basis` — штатный пустой remarks `e3b0c44298fc1c14`, оговорённый в ТЗ.
